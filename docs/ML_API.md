# Lethe ML API (for the integration phase)

Owner: ML builder. Everything runs from the repo root with `uv run`. Only one process should use the GPU
(MPS) at a time; in `lethe/server.py` wrap every call below that touches a model in ONE global
`threading.Lock()` (MPS is not safe for concurrent use from several threads).

## Quick start

```bash
uv run python -m lethe.data                     # writes artifacts/data/{records,val_records,canaries,sources}.jsonl
uv run python experiments/run_spike.py          # trains base (if missing), 4 shards, pooled; runs the whole spike
uv run python experiments/run_spike.py --reuse  # reuse trained weights, re-run the experiments only
```

All trained artifacts are already in `artifacts/models/` (see table below), so the server only needs to load them.

## Data — `lethe/data.py`

```python
from lethe.data import load_corpus, build_corpus, records_text, record_has_canary, generic_text
corpus = load_corpus(seed=0, write=True)   # deterministic; also writes artifacts/data/*.jsonl
corpus.records       # list[Record]   1000 train records (CONTRACT schema: id, source_id, source_type, display_name, text)
corpus.val_records   # list[Record]   held-out records per source (never trained; for utility/val loss)
corpus.canaries      # list[Canary]   34 = 17 inserted + 17 control (CONTRACT schema + "k" (#insertions) + "template")
corpus.sources       # list[dict]     12: {source_id, source_type, display_name, entity, n_records, n_canaries, [retracted_later]}
corpus.by_source()   # {source_id: [Record]}
```

- Sources: 5 tenants (`tenant:acme|bluefin|copperleaf|driftwood|emberline`, 140 records each),
  3 employees (`employee:priya|marcus|lena`, 60 each), 4 news (`news:series-c|outage-report|breach-claim|ai-feature`,
  30 each). `news:breach-claim` has `retracted_later: true` (the article to revoke in the "retraction" demo).
- Canaries: secrets are 5 digits (`alphabet "0-9"`, `length 5`, |R| = 100,000 → max exposure 16.61 bits).
  Tenants have 2 inserted canaries (k=8 and k=4 insertions), employees and news 1 (k=6). Each source also has
  controls (`inserted: false`, `canary_id` `ctrl-*`): same template, never-trained subject, never inserted.
- External corpus hook: if `artifacts/data/corpus.jsonl` exists (CONTRACT record schema, e.g. LLM-generated by
  Gemini via `google-genai`), its texts replace the templated texts for those `source_id`s; canaries are still
  inserted deterministically by `build_corpus`. Retrain base-independent models (shards, pooled) afterwards.
- Writing `artifacts/data/corpus.jsonl` and re-running `run_spike.py` without `--reuse` retrains everything.

## Model — `lethe/model.py`

- Char-level GPT: 4 layers, 4 heads, d=256, context 128, vocab 96 (printable ASCII + `\n`), 3.21 M params, fp32.
- `GPT.seq_logprobs(idx) -> (B,T,V)`, `GPT.cond_logprobs(prefix_ids, conts) -> (N,L,V)` (KV-cached scoring).
- `Ensemble(members, mode="bayes"|"uniform")` — the serving model. Same two methods.
  - `bayes` (default): mixture of the member next-token distributions with weights = member posterior given the
    visible context (Bayesian model averaging, uniform prior). Still a convex combination of shard models only;
    log-loss is within ln(4) per 128-char window of the best member.
  - `uniform`: plain average of next-token probabilities (the CONTRACT's original wording). Kept for comparison;
    held-out loss is much worse (see RESULTS.md), so `bayes` is used for serving. **Contract note:** this is
    still "average next-token probabilities" but with context-dependent weights; please describe it that way in UI.
- `save_model(model, path) -> sha256`, `load_model(path, device=None) -> GPT`, `sha256_file(path)`,
  `get_device()`, `encode(str)`, `decode(ids)`.

## Training / registry / serving — `lethe/train.py`

```python
from lethe.train import (register_assignment, get_assignment, assign_shards, shard_records, train_base,
                         train_shard, train_pooled, set_serving, get_serving, load_serving, load_registered,
                         load_registry, load_by_name, serving_sha256, eval_loss, N_SHARDS)

assignment = get_assignment()                       # {source_id: shard_id}, FIXED at registration (assignment.json)
recs = shard_records(corpus.records, assignment, 0) # records of shard 0

meta = train_shard(shard_id: int, records: list[Record], model_id: str | None = None,
                   epochs=40, lr=6e-4, seed=0, log_every=0,
                   progress_cb: Callable[[int step, int steps, float loss], None] | None = None) -> dict
# fine-tunes artifacts/models/base.pt on exactly `records`, saves artifacts/models/<model_id>.pt
# (default model_id "shard-<id>"), registers it, returns its registry entry:
# {model_id, kind:"shard", shard, path, weights_sha256, sources:[source_id], record_ids:[...], n_records,
#  parent:"base", created_at, timing:{seconds, steps, final_loss, n_chars, epochs}, config, extra}

train_pooled(records, model_id="pooled", ...) -> dict      # same, kind "pooled"
train_base(steps=2000, ...) -> dict                         # generic source-free text; model_id "base"

set_serving({0: "shard-0", 1: "shard-1-v2", ...}) -> {"shards": {...}, "serving_sha256", "updated_at", "assignment"}
#   keys may be int or str ("0".."3" as get_serving() returns them); they are normalized to int.
get_serving() -> same dict (artifacts/models/serving.json); "shards" keys are STRINGS "0".."3"
serving_sha256(model_ids) -> sha256 over the SORTED shard weight sha256 hex strings concatenated (CONTRACT)
load_serving(shard_paths=None, device=None, mode="bayes") -> Ensemble    # default: from serving.json
load_registered(model_id) -> GPT
load_by_name(name) -> GPT | Ensemble   # name in API_MODEL_NAMES:
#   "serving", "pooled", "pooled_unlearned", "pooled_unlearned_quantized", "pooled_unlearned_relearned"
eval_loss(model, text) -> float        # nats/char
```

### Shard assignment is fixed at registration (never recompute it)

`artifacts/models/assignment.json` holds the source → shard map, written once by
`register_assignment(corpus.sources)` (already done; `run_spike.py` calls it too). Sources already in the file
keep their shard; only new sources are placed. **The revoke path must read `get_assignment()` and never call
`assign_shards()`**: `assign_shards` balances over the whole source list, so recomputing it without
`tenant:acme` moves 10 of the other 11 sources to different shards (measured), and you would retrain the wrong
shard. `set_serving()` copies the map into `serving.json["assignment"]`.

- Integration: put each source's `shard` in its `SOURCE_REGISTERED` ledger payload, and have the certificate
  say "partition fixed at registration".
- Honest caveat for the certificate's out-of-scope notes: the partition was computed when the revoked
  source was still present. A system that never had the source could have partitioned the others
  differently, so the post-removal system is not distributed exactly like "never had X". The partition can
  reveal X's existence and record count, never its content.
  (A data-independent rule such as `int(sha256(source_id), 16) % S` would remove even that; not adopted,
  because it would need all shards retrained and gives unbalanced shards at 12 sources.)

### Exact revocation recipe (`POST /api/revoke`, step names from CONTRACT)
```python
assignment = get_assignment()                                    # stored, NOT recomputed
shard = assignment[source_id]
affected = shard_records(corpus.records, assignment, shard)      # 1. blast_radius
keep = [r for r in affected if r["source_id"] not in revoked_sources]   # 2. exclude_records (cumulative set)
meta = train_shard(shard, keep, model_id=f"shard-{shard}-v{n}", progress_cb=cb)   # 3. retrain_shard (~20-45 s)
current = {int(k): v for k, v in get_serving()["shards"].items()}
set_serving({**current, shard: meta["model_id"]})                # 4. redeploy
serving = load_serving()
res = audit(serving, [c for c in corpus.canaries if c["source_id"] == source_id])   # 5. audit
# 6. sign / certificate: ledger builder's code; use meta["weights_sha256"], get_serving()["serving_sha256"]
```
Expect the revoked source's inserted canaries at control level (~0.5–3 bits); also audit the controls for the
baseline `y`. Keep `revoked_sources` cumulative: a second revocation in the same shard must exclude both.

## Audit — `lethe/audit.py`

```python
from lethe.audit import audit, canary_exposure, canary_rank, summarize, generate
res = audit(model_or_ensemble, canaries, source_ids=None) -> list[dict]
# each: {canary_id, source_id, inserted, exposure_bits, max_bits, rank, n_candidates, secret_logprob,
#        exposure_bottom_bits, digit_mass_logprob, secret_prob_given_format,
#        top_candidate, top_candidate_prob_given_format, top_candidate_is_secret, greedy, extracted}
summarize(res, source_ids=None) -> {inserted_mean_bits, control_mean_bits, control_max_bits, extracted,
                                    inserted_ranks, inserted_max_bottom_bits, inserted_min_digit_mass_logprob,
                                    top_candidate_hits, n_inserted, n_control}
canary_rank(model, canary) -> int     # rank only (no greedy decode); used for GA early stopping
generate(model, prompt, max_new_tokens=200, temperature=0.8, top_k=20, seed=0, stop=None) -> str  # completion only
```
- exposure = log2(100000) − log2(rank), EXACT rank over all 100,000 candidates (no sampling).
- `exposure_bottom_bits` = log2(n) − log2(n − rank + 1): exposure read from the BOTTOM of the ranking. If
  approximate unlearning over-suppresses the secret, it lands near the bottom (rank ~98k of 100k), which also
  singles it out. Show it next to `exposure_bits` for unlearned models.
- `digit_mass_logprob` = logsumexp over all 100k candidates = log P(the next 5 chars are SOME 5-digit string).
  ~0 for a healthy model. Very negative (e.g. −84 for the old 100-step GA model) means the model no longer emits
  the format at all, so its rank is a rank among noise.
- `secret_prob_given_format` = P(secret | output is a 5-digit string). Pair it with the rank: "rank 1 of 100k,
  probability 17–31% given a 5-digit output (vs ~90% before unlearning)".
- `top_candidate` / `top_candidate_prob_given_format` = **format-aware extraction**: the attacker's single best
  5-digit guess. Use this in the demo to show a leak ("attacker's best 5-digit guess = 41352, p=0.31"), NOT free
  generation: after relearning, greedy/sampled `generate()` output usually does not contain the secret even at
  rank 1 (e.g. greedy emits "cautiously p..."). `top_candidate_is_secret` says whether that guess is right.
- `greedy` = greedy decoding of 5 chars after the prefix over the full vocabulary; `extracted` = greedy == secret.
  NOTE: `greedy` and `top_candidate` reveal the (synthetic) secret; fine for the demo, never for real data.
- Cost (measured): ~0.45 s per canary for one model, ~1.5 s per canary for the 4-member ensemble
  (all 34 canaries: 15 s / 51 s). In live paths audit only the revoked source's canaries + its controls
  (2-4 canaries -> ~3-6 s on serving); cache full-audit results per serving_sha256 for `GET /api/audit`.

## Approximate unlearning + attacks — `lethe/unlearn.py`, `lethe/attacks.py`

```python
from lethe.unlearn import (approximate_pipeline, unlearn, early_stop_fn, APPROX_DEFAULTS, APPROX_DEMO_SOURCES,
                           APPROX_DEMO_DEFAULT, PASS_BITS, FORGET_SCOPE, RELEARN_DATA)
out = approximate_pipeline(source_id="tenant:acme", corpus=None, save=True, canaries=None, progress_cb=None,
                           demo_only=True, **overrides)
# overrides: method, steps (max GA steps), lr, retain_weight, forget_scope ("flagged"|"all"),
#            early_stop (default True), pass_bits (3.0), check_every (10), seed (0),
#            relearn_steps, relearn_lr, relearn_data ("other"|"same")
# demo_only=True raises ValueError unless source_id in APPROX_DEMO_SOURCES = ("tenant:acme", "tenant:bluefin")
# -> {"source_id", "config": {"unlearn": {..., "stopped_at", "passed"}, "relearn": {...}, "quant": {...}},
#     "unlearn_seconds", "relearn_seconds",
#     "models": {"pooled"|"pooled_unlearned"|"pooled_unlearned_quantized"|"pooled_unlearned_relearned":
#                {"audit": [...], "summary": {...}, "val_loss": float}}}
# save=True writes/overwrites artifacts/models/pooled_unlearned*.pt and their registry entries.

from lethe.attacks import quantize_rtn, relearn
quantize_rtn(model, bits=4, group_size=32, include_embeddings=False) -> GPT   # never reads original weights
relearn(model, records, canaries, steps=30, lr=3e-4, seed=0) -> (GPT, info)   # raises if any record has a canary
```
Defaults: GA, lr 2e-5, retain weight 5, forget set = the source's records that contain its secrets ("flagged",
the most favorable case for the defender), **stopped at the first passing audit**: every inserted canary of the
source at ≤ 3 bits (rank ≥ 12,500 of 100k), checked every 10 steps, at most 150 steps. For acme that is step
70–80. Relearn = 30 steps, lr 3e-4, on canary-free records of OTHER sources. End-to-end ≈ 25–35 s.

Why early stopping: the old fixed 100-step default over-suppressed. It passed the rank audit (1.29 bits),
but the model emitted `nnnnnanantsn` after the prefix, and the total probability of any 5-digit string was
e^-84, so its rank was a rank among noise. The early-stopped model still emits digits after the prefix. Its
secret sits mid-ranking (bottom exposure ≤ 0.8 bits), not at the bottom. See RESULTS.md section 3.

### What the integration must do (measured scope of the claim)
- **Restrict `POST /api/approximate/run` to `APPROX_DEMO_SOURCES`, defaulting to `tenant:acme`.**
  `approximate_pipeline` raises `ValueError` for any other source unless called with `demo_only=False`.
  - The relearning recovery was measured on all 12 sources × 3 seeds (RESULTS.md section 4b). It is strong
    for tenants whose name appears in other sources' records: acme and bluefin.
  - It is partial or absent for the other tenants, and absent for employee and news sources.
- **Never run the approximate contrast on `news:breach-claim` or `employee:priya`.** Use breach-claim only
  for the exact-removal (retraction) story.
- **Showing the leak:** use the audit's `top_candidate` / `secret_prob_given_format` / `rank`, i.e.
  "attacker's best 5-digit guess = 41352 (rank 1 of 100k; P = x% given a 5-digit output, vs ~90% before)".
  **Do not use `POST /api/generate` to show the secret coming back.** Free generation on the relearned model
  starts with words, not digits (greedy "cautiously p…"); RESULTS.md has the samples.
- UI wording for the unlearned model: "passes the canary-rank audit (exposure ≤ 3 bits)". Never say
  "perfectly unlearned". For the relearned model, say "rank 1 of 100,000 5-digit strings (one guess for an
  attacker who knows the format)", not "fully restored".

| `train_shard` after removing one source (exact revocation) | 20–33 |
| `train_pooled` (1000 records) | 137 |
| `unlearn` (GA, 100 steps, no checks) | 10 |
| `unlearn` early-stopped (70–120 steps + a rank check every 10 steps) | ~10–20 (uncontended estimate; 38 s measured while 2 other GPU jobs ran) |
| `relearn` (30 steps) | 2 |
| `quantize_rtn` | < 1 |
| `approximate_pipeline` end to end (unlearn + quantize + relearn + 4 audits of 4 canaries + val loss) | 23 (old 100-step default); see RESULTS.md for the early-stopped default |
| `audit` all 34 canaries: single model / serving ensemble | 15 / 51 |
| `generate` 120 chars: single / ensemble | ~1 / ~3 |

Headline results (details in `experiments/RESULTS.md`):
- **Memorization.** Inserted canaries score 16.61 bits (rank 1 of 100k) on both pooled and serving, against
  ~1.5–2.3 bits for the controls.
- **Exact removal.** It brings the removed source down to 0.5–2.3 bits, inside the control range. This holds
  for all four sources tested (acme, breach-claim, priya, copperleaf). Quantization and relearning do not
  undo it.
- **Approximate unlearning (GA, early-stopped).** It passes the rank audit at 2.3 bits for acme, but the
  model no longer completes the prefix with digits.
- **Relearning attack** (30 steps on OTHER sources' canary-free records). For **tenant:acme**, the secrets
  return to rank 1–2 in all 3 seeds. For c-acme-1 that means P = 63% given a 5-digit output, against 94%
  before unlearning.
  - Recovery is strong for acme and bluefin, the tenants that other sources' records mention by name.
  - It is partial or absent for the other tenants, and absent for employee and news sources. See RESULTS.md
    section 4b for the 12-source × 3-seed table.
  - Do not claim it in general.
- **Quantization.** 4-bit RTN did NOT recover the secrets at this scale (an honest negative result).

## Gotchas for integration

- Registry kinds: `base`, `shard`, `pooled`, `pooled_unlearned` (the quantized and relearned variants also
  use kind `pooled_unlearned`; their `extra.attack` says which). The serving model is not a file; its identity
  is `serving.json["serving_sha256"]` over the member shard hashes.
- `pooled_unlearned*` registry entries list ALL records and sources (including the "forgotten" one). That is
  correct: approximate unlearning does not change what the weights were trained on, so no exclusion
  certificate may be issued for them.
- `train_shard` seeds are deterministic (`seed + 1000*(shard+1)`), but MPS kernels are not bit-exact, so a
  retrain gives a new `weights_sha256` each time. Always hash the saved file (`meta["weights_sha256"]`).
- `relearn()` raises `ValueError` if any record contains an inserted canary prefix or secret.
- Canary secrets are in `artifacts/data/canaries.jsonl` and in audit `greedy` / `top_candidate` output (all synthetic).
- `get_serving()["shards"]` has STRING keys. `set_serving` accepts int or str keys and normalizes them to int,
  so mixed maps no longer crash.
- Never call `assign_shards()` on the revoke path; use `get_assignment()` (see above).
- Platform hooks: `artifacts/data/corpus.jsonl` is the drop-in point for LLM-generated (e.g. Gemini /
  google-genai) realistic records; nothing in the ML code calls external services.
